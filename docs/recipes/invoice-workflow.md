# Проверка счёта и передача человеку

Приложение [examples/invoice_workflow.py](../../examples/invoice_workflow.py) соединяет `document` с
`experimental.process`. Это пример использования текущего API; Process остаётся experimental.
Решение approve означает совпадение суммы и валюты с заказом, а не разрешение оплаты.

```bash
PYTHONPATH=src python examples/invoice_workflow.py --demo /tmp/invoice-demo
```

Демонстрация работает без сети. Читатель распознаёт только заранее подписанные строки и не является
моделью для реальных счетов. Демонстрация сохраняет автоматическое решение, запрос человеку при отсутствии
суммы, пересоздаёт приложение из спецификации, записывает ответ и возобновляет тот же run.

Для своей модели:

```python
from examples.invoice_workflow import InvoiceWorkflow
from solvi.models import llm

workflow = InvoiceWorkflow("invoices", llm(URL, MODEL, api_key=KEY))
result = workflow.run(text, order_total="123.45", currency="EUR")
if result.status == "pending":
    print(result.run, result.ticket, result.why)
# В другом процессе с той же версией модели и кода:
workflow = InvoiceWorkflow("invoices", llm(URL, MODEL, api_key=KEY))
workflow.inbox.answer(ticket, "reject", reviewer="anna", note="сумма отсутствует")
result = workflow.process.resume(run_id)
print(workflow.operator_state(result))
```

Заказ передаётся приложению независимо от модели. Денежная сумма сравнивается через Decimal.
Цитаты остаются в журнале узла `decisions.jsonl`, путь и ответ человека — в `process.jsonl`.
`process-spec.json` связывает версию политики и отпечатки узла. Другой отпечаток не подставляется молча
в старый процесс: создаётся новый каталог версии. Старые записи проверяются с прежним кодом/моделью.

Очередь `inbox` хранит запрос и единственный неизменяемый исход в отдельных JSON-файлах.
Публикация через временный файл и атомарное создание ссылки не открывает частично записанный ответ.
Повторный ответ или ответ после отмены отвергается. `process.cancel(run_id, why)` отменяет ожидание;
повторный resume завершённого run отвергается самим Process.
Очередь рассчитана на доверенный локальный файловый каталог. Для многопользовательского сервиса нужны
аутентификация и собственный HumanChannel; имя reviewer в локальном файле не доказывает личность.

`operator_state` показывает версию, отпечаток, статус и причину, очередь, наличие обещания, состояние
наблюдения за дрейфом и результат проверки журналов/replay. Отсутствие калибровки и монитора показано явно.
Сохранённый ответ человека не переименовывается в автоматический. Replay проверяет записи и процедуру,
но не правильность человеческого ответа и не семантику поля.

Этот пример по умолчанию не калиброван и не даёт статистического ограничения ошибки. Точный опыт
калибровки и сравнения вариантов вынесен в [протокол пилота](../invoice-pilot.md), эксплуатационный
критерий — в [план развития](../development-1.4.1.md). Автоматическое решение в демо не равно сертифицированному.

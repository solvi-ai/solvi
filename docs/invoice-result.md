## Почему модельная часть остановлена

Проверка ключа OpenRouter вернула HTTP 200. Запрос к модели вернул HTTP 403 с сообщением
“The request is prohibited due to a violation of provider Terms Of Service.” Подмена маршрута,
учётных данных или обход запрета не выполнялись. Нужен разрешённый доступный endpoint.

В SQLite сохранены 11 failed-запросов с суммарным резервом $0.0245434. Это **не подтверждённое списание**:
сырых успешных ответов и usage.cost нет. Шесть результатов вариантов на двух smoke-документах — отказы,
ответов нет. Их нельзя трактовать как нулевую точность модели: корректного измерения модели не состоялось.

В smoke также обнаружено отсутствие создания каталога журнала у самостоятельного рецепта. Оно исправлено,
а тест транспорта усилен: требуется точное правильное решение, а не любой ответ, включая None.
После исправления новый платный smoke не запускался. Старый protocol.json сохраняет старые хеши,
поэтому текущая версия кода правильно откажется продолжать тот запуск. Это **не** готовый live-checkpoint.

Исходные четыре файла smoke сохранены отдельно с совпадением SHA-256 прежнего pre-call manifest.
Исходник workflow восстановлен удалением единственной добавленной после smoke строки создания каталога
и проверен по прежнему хешу. В новых запусках source bytes сохраняются до запроса, без такой реконструкции.

## Данные и критерий

Пилотный источник — 200 синтетических счетов из [InvoiceBenchmark](https://huggingface.co/datasets/jngb-labs/InvoiceBenchmark).
После исключения просмотренного при разработке поставщика осталось 190: 169 calibration и 21 eval.
Состав разделения не подбирался по ответам. При 21 eval-примере даже ноль ошибок не позволит получить
требуемую одностороннюю границу 5% с установленной поправкой. Это ограничение дизайна, не результат модели.

Первичный критерий на ≥1000 реальных eval-документах, покрытие и сравнения из
[плана развития](development-1.4.1.md) сохранены. Синтетический пилот не может заменить эту проверку.

## Независимая проверка

Проверка чисел и метода: **BLOCK** исследовательского результата и live-готовности — нет корпусного eval
и успешного smoke. Проверка формулировок: после исправления описания резерва **PASS по wording**;
это не подтверждение полезности метода. Итог остаётся **не подтверждён**.

## Условия продолжения

1. Получить разрешённый endpoint. Не обходить HTTP 403 сменой маршрута или личности.
2. Создать новый протокол/каталог запуска для исправленного кода, сохранив старые доказательства;
   при продолжении текущего бюджета учесть прежние консервативные резервы.
3. Пройти короткий известный smoke, сохранение/возобновление и контроль расходов.
4. Только после этого выполнить один пилот по [протоколу](invoice-pilot.md), затем независимый review-result.
5. Для эксплуатационного вывода подготовить отдельные реальные данные достаточного размера и новый протокол.
